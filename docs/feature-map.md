# Feature map

One row per Vigil feature: the phase that builds it, how you reach it,
where its code lives, which guardrail binds it, what tests it, and whether
it is live. Read this before exploring the repo. When you change a
feature, update its row in the same PR, and update `docs/architecture.md`
if the change moves a flow shown there.

`scripts/check-feature-map.py` runs in CI. It fails when:
- a path in a `shipped` row doesn't exist;
- an API or gateway route in the code is in no row.

**Columns.**
- **Phase**: 1 Core · 2 Review ladder + fleet + CLI/MCP + session proxy
  · 3 Web UI + metering · 4 OpenCode executor · 5 Tower · 6 Post-merge +
  fix jobs + auto-merge · 7 Eval (owner decision 2026-10-22).
- **Entry points**: REST route, CLI command, MCP tool, web page, or GitHub
  trigger. All of them reach the same handler.
- **Guardrails**: where a hard stop is enforced.
- **Status**: `planned (phase N)`, `shipped`, or `blocked by <what>`.
